# K리그 경기 기록 분류 | 데이터마이닝 학습 기록

**한국어** | [English](k-league-prediction.md)

**분류:** 초기 학습 프로젝트<br>
**공개 범위:** 데이터·모델 비교 요약<br>
**해석 기준:** 입력 정보의 시점을 재확인하기 전까지 사전 승부 예측 성과로 제시하지 않습니다.

## 학습한 내용

K League 데이터센터의 경기 기록 1,368개와 24개 변수를 활용해 승·무·패 분류 모델을 비교했습니다. 결측치·이상치·상관관계를 확인하고, 스케일링과 분류기 선택에 따라 결과가 어떻게 달라지는지 살펴봤습니다.

- 전처리: 결측치·분포 확인, Robust scaling
- 비교 모델: Decision Tree, Naive Bayes, KNN, Logistic Regression, MLP, SVM, Bagging, XGBoost
- 평가 항목: Accuracy, Precision, Recall, F1-score
- 해석: 트리 기반 중요도와 Mutual Information으로 변수 확인

## 예측 시점에 대한 점검

기존 소개에는 득점, 유효 슈팅, 코너킥, 클리어링, 경고·퇴장 등을 입력 변수로 적었습니다. 다만 그 값이 **이전 경기에서 계산된 값인지, 예측 대상 경기 종료 후 기록인지**를 설명하지 않았습니다.

동일 경기 종료 후 정보를 사용했다면 경기 전 승부를 예측하는 모델로 해석할 수 없습니다. 따라서 이 사례는 현재 모델 비교 학습 기록으로 분류하고, 다음을 확인해야 사전 예측 프로젝트로 확장할 수 있습니다.

1. 변수별 관측 가능 시점과 과거 경기 집계·시차 처리 여부
2. 경기 날짜를 기준으로 한 학습·검증 분리
3. 동일 경기·팀의 중복과 전처리 과정의 정보 누수 여부
4. 다수 클래스·홈팀 기준 모델 대비 성능

## 기존 기록의 보존

기존 문서에는 Bagging Accuracy 63.44%, F1-score 58.67%가 기록되어 있습니다. 검증 조건을 재확인하기 전까지 이 숫자는 학습 기록으로만 남기며, 일반화된 사전 예측 성능으로 사용하지 않습니다. 현재 설명만으로 실제 누수 발생 여부를 확정한 것은 아닙니다.

## 배운 점

모델 종류나 평가 점수보다 먼저 ‘예측할 때 실제로 알 수 있는 정보인가’를 정의해야 한다는 점입니다. 이후 프로젝트를 설명할 때도 데이터 기준 시점과 검증 단위를 함께 기록하는 기준으로 삼습니다.
